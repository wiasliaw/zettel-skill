# /zk:query

**全程唯讀**：不寫入任何檔案、不更新索引、不觸碰日誌；查詢前後 vault 內容與 `.qmd/` 索引一致。沒有模式分派，單點查詢只是廣度召回自然收斂到一兩筆命中的特例。

## 流程

1. **前置**：確認 vault root 存在 `.zettel.json`；不存在則停止並引導執行 `/zk:init`。活讀 config 取得 `permanent.place`、`reference.place` 與 `qmd.enabled`。

2. **廣度召回**：範圍限 filed 兩目錄，依 `${CLAUDE_PLUGIN_ROOT}/skills/internals/recall.md` 執行——`qmd.enabled: true` 走 qmd 主漏斗（呼叫前置與 args 拼接依該檔；廣度召回時 MAY 於對話中放寬篩選，例如多取候選），`false` 走 Grep 降級；無論何者另加精確詞 Grep 與檔名比對，命中併入同一候選池。

3. **深度閘門（讀全文鐵律）**：讀答案實際會引用或依賴的候選全文，通常 2 到 5 篇，其餘略讀至足以排除。相似度分數與命中次數單獨不構成引用理由；高分候選也必須先讀全文才可能被引用。

4. **綜合作答**：以讀過全文且行文確實論及查詢主題的筆記為據作答，引用處以 `[[note]]` 標示。

5. **一跳漫遊**（serendipity）：
   - 收集深度閘實際讀過全文之筆記行文內的全部出鏈 `[[wikilink]]` 目標。
   - 排除已在候選池與已讀集合內的目標——剩下的即「檢索沒帶你來、但已讀筆記行文指向」的遠端筆記。
   - 讀剩餘目標全文，上限 5 篇；超過上限時優先取被多篇已讀筆記共同指向者，其餘依出現順序取足。
   - 回報「漫遊發現」一節：每筆列目標筆記與其與查詢主題的意外關聯（一句話）。讀後判定無實質關聯者不硬寫；本次無發現時該節明寫「無」，不省略該節（讓漫遊有沒有跑過可觀察）。

6. **缺口回報**：把查詢觸及卻無法完整回答的空白處與矛盾之處，指出為下一步書寫方向，作為誠實但書。缺口不等於窮盡列出所有可能主題——例如查詢「哪些筆記涵蓋某機制的邊界條件」而召回筆記只談機制本身時，缺口寫成「slip-box 目前未涵蓋該機制的邊界條件，可作為下一篇筆記的方向」，而非判定整個查詢無法回答。

## 回報格式

最終訊息 MUST 依序含：作答本文（含 `[[note]]` 引用）、漫遊發現一節（無發現時明寫「無」）、知識缺口一節。被另一指令包裹呼叫時，此回報原樣出現在該輪最終訊息，不得壓縮成外層摘要的一行。
